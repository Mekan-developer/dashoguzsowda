# Изменения API — комиссия платформы (03.09.2026)

Всё, что появилось в бэкенде после того, как заказы и магазины были подключены.
Покупательская часть API **не изменилась** — трогать её не нужно.

Меняется только экран владельца магазина: у каждого магазина своя ставка
комиссии, её задаёт админ, и владелец теперь видит, сколько с заказа получит.

---

## 1. `GET /v1/my/store` — одно новое поле

```json
{
  "data": {
    "id": 3,
    "name": "Altyn Bazar",
    "status": "approved",
    "is_active": true,
    "commission_percent": 5
  }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `commission_percent` | number | Комиссия платформы с проданного товара. `0` — комиссии нет |

**Только для чтения.** В `POST` / `PUT /v1/my/store` это поле не принимается:
ставку задаёт админ в панели, владелец её лишь видит. Отправите — будет
проигнорировано.

---

## 2. `GET /v1/my/store/orders` и `/{id}` — три поля в части заказа и два в позиции

```json
{
  "data": {
    "id": 21,
    "order_number": "000017",
    "order_status": "approved",
    "status": "pending",
    "subtotal": 200,
    "commission_percent": 5,
    "commission": 10,
    "payout": 190,
    "can_respond": true,
    "items": [
      {
        "id": 44,
        "listing_id": 108,
        "title": "Рис длиннозёрный",
        "unit_price": 100,
        "is_wholesale": false,
        "qty": 2,
        "total": 200,
        "commission": 10,
        "payout": 190,
        "photo": "https://.../thumb.webp"
      }
    ],
    "created_at": "2026-09-02T12:00:00+00:00"
  }
}
```

| Поле | Где | Тип | Описание |
|---|---|---|---|
| `commission_percent` | часть заказа | number | Ставка магазина **на момент оформления** заказа |
| `commission` | часть заказа | number | Сумма комиссии: `subtotal × commission_percent / 100` |
| `payout` | часть заказа | number | Что остаётся магазину: `subtotal − commission` |
| `commission` | позиция | number | Комиссия с этой позиции |
| `payout` | позиция | number | `total − commission` по позиции |

Те же поля приходят в ответах `POST /v1/my/store/orders/{id}/accept`
и `/decline` — там тот же объект части заказа.

---

## 3. Что важно понимать

**Комиссия удерживается с магазина, а не добавляется покупателю.**
Покупатель платит `subtotal` целиком — ровно ту сумму, которую видел в корзине.
Магазину причитается `payout`.

```
Рис 100 ман × 2            = 200 ман   ← платит покупатель
Комиссия магазина 5 %      =  10 ман   ← удерживает платформа
Магазину к получению       = 190 ман
```

**Ставка — снимок на момент заказа.** Админ может изменить процент магазина;
уже оформленные заказы считаются по прежней ставке. Поэтому
`commission_percent` в части заказа может отличаться от `commission_percent`
в `/v1/my/store` — это не рассинхрон, а так и задумано. Показывайте на экране
заказа именно значение из заказа.

**Покупателю комиссия не отдаётся нигде.** В `GET /v1/orders`,
`GET /v1/orders/{id}` и `POST /v1/orders` полей комиссии нет и не будет.
Не показывайте её ни на одном покупательском экране.

**Ставка 0 — обычный случай.** У магазина, которому админ ещё не назначил
процент, `commission_percent = 0`, `commission = 0`, `payout = subtotal`.
При нуле блок комиссии на экране лучше не рисовать вовсе.

---

## 4. Что сделать в приложении

1. В модель магазина (`/v1/my/store`) добавить `commissionPercent`.
2. В модель части заказа — `commissionPercent`, `commission`, `payout`.
3. В модель позиции заказа магазина — `commission`, `payout`
   (у покупательской позиции этих полей нет — если модель общая, сделайте их
   nullable или заведите отдельную).
4. На карточке части заказа при `commission_percent > 0` показать строку вида:

```
Сумма заказа        200 ман
Комиссия 5 %        −10 ман
К получению         190 ман
```

При `commission_percent == 0` блок не показывать.

5. Ничего не менять на экранах покупателя.
