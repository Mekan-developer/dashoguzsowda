# Заказы: продавец вместо админа, один магазин на заказ

Сентябрь 2026. Меняется порядок работы с заказами — правки нужны и в экране
корзины, и в «Моих заказах», и во вкладке магазина. Полное описание —
`BACKEND_API.md` §15.

## Что изменилось по сути

1. **Заказ ведёт владелец магазина, а не админ.** Он принимает заказ,
   доставляет сам и отмечает доставленным. Админ только смотрит.
2. **Один заказ — один продавец.** Заказать в один момент у нескольких
   магазинов нельзя.
3. **Продавец видит контакты и адрес покупателя** — иначе не доставить.
4. **Покупатель видит телефон продавца** и решает вопросы напрямую с ним.

## Что делать мобилке

### 1. Корзина делится по магазинам (обязательно)

Корзина по-прежнему локальная, но показывать её надо секциями по магазинам:
своя секция, своя сумма и своя кнопка «Оформить» у каждого магазина.
`POST /v1/orders` отправляется **на каждый магазин отдельно** — сколько
магазинов, столько заказов.

Если в один запрос попадут товары двух магазинов, придёт `422`:

```json
{ "message": "...", "errors": { "items": ["В одном заказе может быть товар только одного магазина — оформите заказ каждому продавцу отдельно"] } }
```

### 2. Переименованные поля в заказе покупателя

| Было | Стало |
|---|---|
| `admin_comment` | `decision_comment` — причина отказа **продавца** |
| `processed_at` | `decided_at` |

`stores[]` остался массивом, но в нём всегда один элемент. Телефон продавца —
`stores[0].store.phone`, его ответ — `stores[0].comment`.

### 3. Новый эндпоинт у магазина: «Доставлено»

```
POST /v1/my/store/orders/{id}/complete
```

Кнопку показываем по флагу `can_complete` (доступен после «Принять»).

### 4. Новые поля в заказе магазина

```json
"can_complete": true,
"buyer":    { "name": "Merdan", "phone": "+99361234567" },
"delivery": { "address": "...", "region": {...}, "city": {...}, "district": null, "comment": "Позвонить за час" }
```

Показываем их на карточке заказа: имя, телефон (кнопка «Позвонить»), адрес и
пожелание покупателя.

### 5. Тексты и статусы

- «Заказ оформлен, администратор свяжется» → «Заказ отправлен продавцу».
- `approved` = «Продавец принял», `rejected` = «Продавец отказался»,
  `completed` = «Доставлен», `canceled` = «Отменён покупателем».
- Отмена возможна, только пока продавец не ответил (`can_cancel`), после —
  422 с текстом «Продавец уже принял заказ — свяжитесь с ним по телефону».

### 6. Push

Новых типов нет: заказу покупателя — `order`, заказу магазина — `store_order`.
Добавилось событие «покупатель отменил заказ» (владельцу, `store_order`).
