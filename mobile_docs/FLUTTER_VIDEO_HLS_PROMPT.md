# Задача: перевести воспроизведение роликов на HLS

Ты работаешь во Flutter-приложении доски объявлений (Sowda). Бэкенд — Laravel.
Ролики (шортсы) теперь нарезаются на сервере в **адаптивный HLS**: несколько
качеств (360p / 540p / 720p), сегменты по 2 секунды, плеер сам выбирает качество
по скорости сети. Нужно, чтобы приложение играло HLS, а mp4 оставался запасным
вариантом.

Задача небольшая: новых эндпоинтов нет, поменялось одно поле в модели ролика
и логика выбора ссылки в плеере.

## Базовые вещи

- **Base URL:** `https://dashoguzsowda.com.tm/api`, префикс `/v1/...`
- **Auth:** `Authorization: Bearer {token}` — как и раньше, все эндпоинты
  роликов требуют токен.
- **Именование полей:** `snake_case`.
- Эндпоинты роликов не менялись: `GET /v1/videos`, `GET /v1/videos/my`,
  `GET /v1/videos/{id}`, `POST /v1/videos`,
  `POST /v1/videos/upload/{upload_id}/complete`.

---

## Главные правила — прочитай до того, как писать код

### 1. У ролика новое поле `hls`

```json
{
  "id": 42,
  "processing": false,
  "video":   "https://dashoguzsowda.com.tm/storage/videos/9b1c.../processed.mp4",
  "hls":     "https://dashoguzsowda.com.tm/storage/videos/9b1c.../hls/master.m3u8",
  "preview": "https://dashoguzsowda.com.tm/storage/videos/9b1c.../preview.jpg"
}
```

- `hls` — `String?`, ссылка на `master.m3u8`. Может быть `null`.
- `video` — `String`, как и раньше, mp4. Никуда не делся.
- `preview` — `String?`, постер. Как и раньше.

### 2. Какую ссылку отдавать плееру

```dart
String get playbackUrl => hls ?? video;
```

Это всё правило. **Не строй ссылку на HLS сам** из `video` или uuid — бери
только из поля `hls`.

| Состояние | `processing` | `hls` | что играть |
|---|---|---|---|
| Готов | `false` | ссылка | `hls` |
| Готов, но HLS нет (старый ролик или нарезка не удалась) | `false` | `null` | `video` |
| Ещё обрабатывается | `true` | `null` | **ничего** — заглушка |

`hls = null` у готового ролика — штатная ситуация, а не ошибка.

### 3. Пока `processing == true` — не играть

Сразу после загрузки ролик приходит с `processing: true`. В этот момент `video`
указывает на **сырой оригинал** с телефона: это может быть `.mov`/`.mkv`
размером в сотни мегабайт, и не каждый плеер его откроет. Такой ролик
показываем постером/плейсхолдером с бейджем «Обрабатывается», плеер
не создаём.

Чаще всего это видит автор: в ответе на загрузку и в `GET /v1/videos/my`.
В общей ленте такое бывает редко (модератор успел одобрить ролик раньше, чем
закончилась обработка), но проверка `processing` должна работать и там —
одна и та же для всех экранов.

### 4. Качество выбирает плеер, не ты

Никакого переключателя качества в UI не нужно: `video_player` не умеет
выбирать дорожку, а для роликов до минуты это и не нужно — плеер стартует
с низкого качества и поднимается сам.

## Модели

Добавь поле в существующую модель ролика (имена классов — как уже принято
в проекте):

```dart
class Video {
  final int id;
  final String title;
  final String video;      // mp4, запасной вариант
  final String? hls;       // master.m3u8, может быть null
  final String? preview;
  final bool processing;
  final int durationSeconds;
  // ... остальные поля без изменений

  String get playbackUrl => hls ?? video;
  bool get isPlayable => !processing;
}
```

В маппере:

```dart
hls: json['hls'] as String?,
processing: json['processing'] as bool? ?? false,
```

## Что нужно собрать

### 1. Плеер на HLS

Пакет — `video_player` (ExoPlayer на Android, AVPlayer на iOS), HLS он играет
из коробки, отдельный пакет не нужен. Ссылка оканчивается на `.m3u8`, поэтому
`formatHint` не указывать. Если в проекте `chewie` / `better_player_plus` —
они работают поверх того же движка, просто передай им `playbackUrl`.

Создание контроллера с запасным mp4 — если HLS не стартовал, один раз
пробуем `video`:

```dart
Future<VideoPlayerController> openVideo(Video v) async {
  final urls = [if (v.hls != null) v.hls!, v.video];

  for (final url in urls) {
    final c = VideoPlayerController.networkUrl(Uri.parse(url));
    try {
      await c.initialize();
      if (!c.value.hasError) {
        await c.setLooping(true);
        return c;
      }
    } catch (_) {}
    await c.dispose();
  }

  throw VideoUnavailableException();
}
```

Вызывай его **везде**, где сейчас создаётся `VideoPlayerController` для ролика
(лента, карточка ролика, «Мои ролики»), — не должно остаться мест, где плееру
передаётся `video` напрямую.

### 2. Лента шортсов

- Живыми держи не больше **трёх** контроллеров: текущий, следующий
  (предзагружен через `initialize()`, без `play()`) и предыдущий. Остальные —
  `dispose()`. Иначе на Android кончаются аппаратные декодеры, и плеер
  молча показывает чёрный экран.
- Пока контроллер инициализируется — показывай `preview` (если он не `null`).
- Просмотр засчитывать, как и раньше: `POST /v1/videos/{id}/view`, когда
  ролик реально начал играть.

### 3. Кэш

Если сейчас mp4 кэшируются на диск (`flutter_cache_manager` и т.п.) — для HLS
этот кэш **не применяй**: плейлист и сегменты — это много мелких файлов,
и кэш-менеджер их не соберёт. Сервер сам отдаёт сегменты с
`Cache-Control: max-age=604800`, сеть их закэширует. Для запасного mp4
существующий кэш можно оставить.

### 4. «Мои ролики» и экран после загрузки

- Если `processing == true` — плейсхолдер + бейдж «Обрабатывается», без плеера.
- Обработка идёт от десятков секунд до нескольких минут. Обновляй список
  при возврате на экран и по pull-to-refresh. Если хочется автообновления —
  не чаще раза в 10–15 секунд и только пока в списке есть ролики
  с `processing == true`.
- Тексты «Обрабатывается» — из локализации приложения (tk/ru), сервер
  их не отдаёт.

## Обработка ошибок

- HLS не открылся → тихо пробуем `video` (см. `openVideo`), пользователю
  ничего не показываем.
- Не открылся и `video` → плейсхолдер «Видео недоступно» на месте ролика,
  лента листается дальше. Не роняй экран и не показывай диалог.
- Плеер упал посреди воспроизведения (`controller.value.hasError` в listener) —
  то же самое: плейсхолдер, без диалогов.

## Локальная разработка

Ссылки `hls` / `video` / `preview` строятся на бэкенде из его `APP_URL`.
С `http://localhost:8000` эмулятор и телефон по ним не достучатся:

- Android-эмулятор — на бэкенде `APP_URL=http://10.0.2.2:8000`;
- живое устройство — `APP_URL=http://<IP компьютера в сети>:8000`;
- для `http://` в debug-сборке нужен cleartext:
  - Android — `android:usesCleartextTraffic="true"` в
    `android/app/src/debug/AndroidManifest.xml`;
  - iOS — `NSAppTransportSecurity → NSAllowsArbitraryLoads = YES`, только
    в debug-конфигурации.

В релиз эти исключения не попадают — прод работает по `https`.

## Порядок работ

1. Поле `hls` в модели и маппере, геттер `playbackUrl`.
2. `openVideo()` с запасным mp4, замена всех мест создания контроллера.
3. Заглушка для `processing == true` в «Моих роликах» и после загрузки.
4. Лимит трёх контроллеров в ленте, предзагрузка следующего.
5. Отключить дисковый кэш для HLS-ссылок, если он был.

## Чего делать не нужно

- Не строй ссылку на `master.m3u8` сам — бери только из поля `hls`
- Не удаляй поддержку `video` — без неё не сыграют старые ролики
- Не делай переключатель качества — плеер выбирает сам
- Не подключай отдельные HLS-пакеты — `video_player` справляется
- Не играй ролик, пока `processing == true`
- Не скачивай сегменты HLS в свой дисковый кэш

## Как проверить

В репозитории бэкенда есть Bruno-коллекция, папка `Videos`: «Feed_Public»,
«Get_Single», «My_Videos», загрузка кусками (`Upload_Chunked_*`). Порядок:
Auth → «Отправить SMS-код» (код пишется в `storage/logs/laravel.log`
на дев-стенде) → «Подтвердить код», токен сохранится сам.

Что посмотреть:

1. В ленте у одобренных роликов `hls` заполнен — ролик стартует быстро,
   на медленной сети (ограничь в эмуляторе / Network Link Conditioner на iOS)
   картинка сначала мягче, потом становится чётче.
2. Загрузи ролик → в ответе `processing: true`, `hls: null` → в «Моих роликах»
   бейдж. Через минуту-две после обновления — `processing: false`, `hls`
   заполнен, ролик играет.
3. У ролика с `hls: null` и `processing: false` играет mp4.
4. Подставь в `hls` заведомо битую ссылку (в отладке) — должен сыграть
   запасной `video` без ошибок на экране.
