# Способ оплаты заказа

Сентябрь 2026. Дополнение к `BACKEND_API.md` §1 (магазины) и §15 (заказы).

## Что изменилось

При оформлении заказа покупатель теперь может сказать, **чем он рассчитается**.
Онлайн-оплаты по-прежнему нет: деньги продавец получает сам при доставке — это
договорённость, а не платёж. Но продавцу важно знать её заранее: от способа
зависит, везти ли сдачу или терминал.

Набор способов — свой у каждого магазина. Общий список ведёт админ
(«Настройки → Оплата»), магазин отмечает в нём свои, покупатель выбирает только
из набора того магазина, у которого оформляет заказ.

Стартовый набор справочника: **наличные при получении**, **перевод на карту**,
**терминал при доставке**. Он может пополняться без релиза приложения, поэтому
бэкенд отдаёт названия на двух языках, а не коды — рисуйте список тем, что
пришло, и не зашивайте варианты в мобилку.

## Магазин: `payment_methods`

`StoreResource` (`GET /v1/stores`, `/stores/popular`, `/stores/{id}`,
`/v1/my/store`, а также `store` в профиле) получил поле:

```json
"payment_methods": [
  { "id": 1, "name_tk": "Alanyňda nagt", "name_ru": "Наличные при получении" },
  { "id": 3, "name_tk": "Eltip berlende terminal", "name_ru": "Терминал при доставке" }
]
```

Минимум один элемент есть всегда. У магазинов, созданных до этого изменения,
там «Наличные при получении» — так они и работали.

### Владелец магазина настраивает свой набор

`POST` / `PUT /v1/my/store` принимают `payment_method_ids[]` (multipart, как
остальные поля):

- поле не прислано при **создании** → магазин получает первый способ из
  справочника (наличные). Старая версия приложения продолжает создавать
  магазины как раньше;
- поле не прислано при **правке** → набор не меняется;
- пустой массив → `422`, `errors.payment_method_ids`. Хотя бы один способ
  обязан остаться, иначе покупателю нечего выбрать;
- выключенный админом способ → `422`, `errors.payment_method_ids.0`.

Правка набора **не отправляет магазин на перемодерацию** — это рабочая
настройка, как телефон и доставка.

Экран «Мой магазин»: чекбоксы по списку справочника. Полный список взять
неоткуда отдельным запросом — берите `payment_methods` своего магазина плюс
то, что придёт в карточках других магазинов; отдельного справочного эндпоинта
намеренно нет, набор магазина самодостаточен для всех экранов покупателя.

## Заказ: `payment_method_id`

`POST /v1/orders` принимает новое **необязательное** поле:

```json
{
  "items": [{ "listing_id": 108, "qty": 2 }],
  "address": "ул. Магтымгулы, 12, кв. 5",
  "payment_method_id": 3
}
```

- `null` / не прислано → как раньше: способ не выбран, стороны договорятся по
  телефону. Ничего не ломается, обновление мобилки не обязательно;
- id не из набора этого магазина (или выключенный) → `422`,
  `errors.payment_method_id` — текст локализован, показывайте как есть.

Экран оформления: радиокнопки из `store.payment_methods` того магазина, чью
корзину оформляем. Магазин у заказа всегда один, так что набор однозначен.

## Где виден выбор

`OrderResource` (`GET /v1/orders`, `/v1/orders/{id}`) — у покупателя:

```json
"payment_method": { "id": 3, "name_tk": "Eltip berlende terminal", "name_ru": "Терминал при доставке" }
```

`StoreOrderResource` (`GET /v1/my/store/orders`, `/{id}`) — у продавца, там же
рядом с `buyer` и `delivery`. Показать заметно: продавец едет за деньгами и
должен приехать готовым. `null` — способ не выбран, решат по телефону.

## Чек-лист для мобилки

```
1. Карточка магазина: показать payment_methods (иконку выбирайте по id
   стартовых трёх, для остальных — общая)
2. Мой магазин: чекбоксы payment_method_ids[], не дать снять все
3. Оформление заказа: радиокнопки из store.payment_methods + «не выбрано»,
   отправить payment_method_id (можно не отправлять)
4. Мои заказы и заказы магазина: строка «Оплата» из payment_method
5. 422 errors.payment_method_id — показать текст как есть
```
