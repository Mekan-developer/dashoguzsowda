# Геолокация покупателя в заказе

## Что изменилось

`POST /v1/orders` принимает два новых **необязательных** поля — точку доставки
с телефона покупателя. Продавец везёт заказ сам и по ней находит, куда ехать.

| Поле | Тип | Правила |
|---|---|---|
| `lat` | number | −90…90, только вместе с `lng` |
| `lng` | number | −180…180, только вместе с `lat` |

```json
{
  "items": [{ "listing_id": 10, "qty": 1 }],
  "address": "ул. Магтымгулы, 12",
  "lat": 37.9601,
  "lng": 58.3261,
  "payment_method_id": 1
}
```

Одна координата без другой или значение вне диапазона → `422`
(`errors.lat` / `errors.lng`). Не дали доступ к геолокации — поля просто
не отправлять, заказ оформится с адресом текстом, как раньше. `address`
остаётся обязательным.

## Где точка приходит обратно

- Покупателю: `GET /v1/orders`, `GET /v1/orders/{id}` и ответ на создание —
  `data.location: { "lat": 37.9601, "lng": 58.3261 }` или `null`.
- Продавцу: `GET /v1/my/store/orders`, `GET /v1/my/store/orders/{id}` —
  `data.delivery.location`, тот же формат. Кнопка «Открыть в картах»
  показывается, только когда `location` не `null`.

## Что сделать в мобилке

- На экране оформления запросить геолокацию (можно с кнопкой «Моё
  местоположение») и отправить `lat`/`lng`. Отказ в доступе — не ошибка.
- В заказе магазина показывать точку на карте / ссылку в навигатор.
